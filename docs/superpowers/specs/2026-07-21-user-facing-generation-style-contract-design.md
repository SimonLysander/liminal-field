# 面向用户的生成文本规范设计

## 目标

对直接展示给用户的核心生成文本建立不可被用户指令覆盖的书面表达规范。规范按产品用途分层，不以同一种“教科书腔”覆盖所有场景。

## 范围

纳入以下四类出口：

1. Aurora 对话、写作建议与审稿结论。
2. AI 初稿、学习规划及其审批摘要。
3. 简报刊头、导语与正文。
4. 行内续写与改写。

画廊图说维持简短、具有意象的既有定位；内部记忆、检索结果、研究中间产物和任务计划不纳入本规范。

## 分层标准

### 对话、建议与审稿

采用专业书面语，结论直接，依据和修改动作明确。禁止口语俗词、网络用语、俚语、客服腔及故作亲近的表达，但不要求写成教科书正文。

### AI 初稿与学习规划

采用教科书式严谨表述：概念边界清楚，术语前后一致，因果链条完整，限定条件充分。不得以口语化类比、含混代称或修辞替代必要解释。

### 简报

采用专业事实编辑风格：忠于来源，明确区分事实、来源观点与编辑判断，使用准确、克制的措辞。禁止口语、宣传语和趋势口号；不要求为教学目的展开基础概念。

### 行内续写与改写

保持正文体裁、结构和信息密度，但最低标准为规范书面语。原文或用户指令中的口语表达不构成继续生成口语俗词的依据；必要时在不改变原意的前提下规范化表达。

## 提示词落点

- `agents/user-facing-prose-contract.md`：对话、建议、审稿以及由指定 agent 生成的初稿、规划和审批摘要的共享硬约束，通过 `contextPromptFiles` 精确挂载；图说 agent 不挂载。
- `digest/compose-*.md`：稳定编辑规则进入 `system`，外部标题、理由与原文仅作为 `prompt` 数据输入，避免资料文字覆盖规则。
- `skills/note-writing.md`、`skills/note-plan.md`：分别强化初稿和规划的教科书式严谨标准。
- `digest/compose-plan.md`、`digest/compose-write-section.md`：强化简报的事实编辑标准，并清理可能诱导口语输出的提示词措辞与示例。
- `inline-assist/continue-system.md`：在保持正文体裁的同时执行规范书面语下限。

不修改工具协议、数据结构、输出格式、页面结构或审批流程。

## 验证

- 增加提示词契约测试，确认四类出口都包含对应规范，且行内续写不再无条件复制口语语气。
- 执行服务端与客户端类型检查、lint、单元测试和生产构建。
